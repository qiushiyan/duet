# CLAUDE.md

## What

`duet` — personal semi-AFK orchestrator for one developer's two-worker workflow: a read-only LLM **orchestrator** routes a snippet protocol between each stage's **duty pair** (planning's architect + analyst; delivery's builder + critic-or-judge), inside a code-enforced statechart whose human gates agents cannot cross. A run picks one **workflow** — the thorough `full` (spec → plan → … → PR), the middle `blueprint` (one design doc replaces the pair → … → PR), the criss-crossed `relay` (blueprint's shape; a fresh builder implements the doc, a writing judge fixes findings and owns docs + PR), the lighter `short` (research → implement → … → PR), or a project-composed definition (`duet/workflows` SDK — the same grammar the shipped four are written in, frozen per run) — a workflow being an ordered list of **stages** (planning, delivery) whose phases are compositions of blocks with knobs, not hand-built pipelines (`docs/automation-design.md` §"The workflow vocabulary"; the ratified glossary is `CONTEXT.md`). Repo = design docs (authoritative for _what_ to build) + implementation at root (pnpm + TS, no build step in dev).

Product goals — the bar every change is measured against:

- **Augment, never lock in.** Same CLIs, same snippets, standard transcripts and normal branches; manual takeover and resume must always work; the state file is a hint, never an obstacle.
- **The human owns substance.** The orchestrator does triage, never opinions; product/direction/environment questions always reach the human; gates are structural (statechart), not prompt-enforced.
- **Semi-AFK.** By default the human walks away after the spec (full's `overnight` posture auto-crosses plan, Ship, and the Open-PR gate), after the one Design gate (blueprint's and relay's one-interruption default), or after Direction (short); the handoff gate — planning's last phase (full: plan; blueprint/relay: design; short: research) — is where an _interactively-orchestrated_ run hands its session off to the headless driver. Return to an open PR or a well-formed queued question. Nothing runs between quiescent stops — no daemon.
- **Personal tool first, publish-ready.** Project knowledge enters only via the framing turn; the only config is per-duty (and orchestrator/consultant) provider bindings; exactly two providers. Shipped artifacts (`skills/`, README) are written for any user.

**Status** (detail in `README.md`): the full and short workflows are live-verified end to end — both orchestrator hosts, the consultant, the acceptance contract, run-supervision, the interactive transport, the shared `finish` finishing tail, and `duet stats` have all run on real work; the duty-keyed remodel and the workflow SDK got their first live run together via a project-composed workflow (gateless `deep-relay` to an open PR, 2026-07-05). The shipped blueprint and relay workflows are built and test-verified, awaiting their first live runs (their underlying worlds carry that run's evidence). Codex-as-orchestrator is deliberately unbuilt.

## Invariants that bite if forgotten

Cross-cutting rules; full reasoning in `docs/engineering.md` and `docs/open-questions.md`.

- **Cooperative pause.** `ask_human`/`advance_phase` persist a marker and end the turn; mechanical SDK pauses corrupt resume (repros in `src/spike/`).
- **Gate-crossing is un-forgeable by vocabulary.** A phase emits `phase.*`; only `human.*` crosses a gate; no tool emits `human.*` (in-process, over MCP, or from a Bash-equipped interactive session), so `advance_phase` only ever parks.
- **The terminal marker** is the cross-process phase decision — cleared deliver-before-clear, guarded by the spent-marker check (keyed off the _restored snapshot_), so a crash can't replay a stale decision over a human's answer/reject.
- **Compaction & context pressure:** claude workers compact via a literal `/compact` prompt; codex auto-compacts and must never be sent a command. Headless claude never compacts itself, so duet meters each persistent claude worker's fill and owns the bands — 75% due, 85% enforced (refuse/cut, salvage, reset) — acting on the high-water reading since the last compact; every intervention is ledgered in `contextEvents`, never silent (`docs/automation-design.md` §"Resilience for the AFK window").
- **One branch per run,** fixed before the first worker prompt.
- **Worker budget is per-turn, opt-in, off by default** (off ≡ absent, never `0`); it must never shape scope; a hit cap is a resumable checkpoint, not an infra crash.
- **Bindings are duty-keyed and frozen at the manifest.** Every voice (orchestrator, consultant, each duty) resolves per key — flags (`--bind <duty>=<provider[:model][@effort]>`) > framing `bind.*` > config `[duties.*]` tables > shipped defaults — once at `createRun` (`resolveRunConfig`), frozen on state, echoed by `duet new`. A binding carries the model (both providers — codex defaults to `~/.codex/config.toml`, overridable inline), a normalized **effort** (validated fail-closed per provider), and a config-only **native passthrough** (`claude_args`/`codex_config`) duet never parses; one carrying an explicit model or native override is **preflighted at `duet new`** (`preflight.ts`), so a provider-rejected argument fails at creation, never mid-build. `voiceBindingFor` is the **one** "who runs this turn" resolver (no phase parameter — a duty names its stage); worker construction, session identity, the context-pressure scope, stats, and takeover all read it. Cross-stage session continuity is a registry **continuity edge** (full/blueprint/short: builder←architect + critic←analyst; relay: none — fresh delivery); an edge whose duties' frozen bindings cross providers **degrades to fresh at the freeze** — echoed and ledgered, never an error, never silent — and the build brief adapts the ritual (seed from the committed document, never `/compact` a session the duty doesn't have). Session records are provider-qualified; a mismatch derives fresh, so a cross-provider resume stays unrepresentable.
- **A run carries its frozen workflow.** `createRun` writes the compiled workflow to `.duet/runs/<id>/workflow.json` (shipped workflows included), and every later process reads that artifact through `workflowFor`; workflow source files are never read after creation, so editing or deleting one cannot corrupt a live run.
- **Write authority is lane-based, action-scoped, and resolver-read.** Makers write, checkers are read-only; run-aware widening goes through `writeAuthorityFor(state, phase, address, action)` — relay's judge widens for `review-and-fix` and its owned tails only, never a midpoint read — and it keys `settleTurn`'s `verifiedAt` staleness, so the writing judge stales a verification like the builder. Behavior keyed on a snippet tag reads `ACTION_CATALOG` (a code map beside the registry), never the tag's spelling — snippet-body overrides must never be able to change behavior.
- **`gates_at` is the complete attend set, not a delta** (so `--gates-at finish` attends only the Open-PR gate). full's default posture is `overnight` (attend frame,spec); blueprint's and relay's is attend-`design`-only (one interruption); every workflow's Open-PR gate sits _after_ the open and auto-crosses the auto-opened PR by default; an attended gate still takes a human tap, as does the interactive orchestrator's one `ask` rule on `duet continue`. An empty `gatesAt: []` is attend-_none_ (distinct from absent ⇒ attend-all); **gateless** (`--gateless`/`gateless:`) is that posture plus dropping the consultant's holding bet-audit (its non-holding frame + the contract/verify backstop still run) — walk away from the _start_ (`docs/automation-design.md` §Gate pre-authorization).
- **A `high` `human_decisions` entry** holds a non-explicit crossing (`gates_at` auto-cross, bare `duet afk`) but not an explicit one (`--approve`; `duet afk --gateless`, the deliberate full-send, crosses the bet/product highs too — yet even it preserves the acceptance-contract backstop, refusing to hand off when no contract was authored).
- **Steers live in `steers/`, never `state.json`** (a CLI write there would race the live driver's saves); deliver-then-consume, so a crash redelivers a steer rather than loses one.
- **Runtime artifacts under self-ignored `.duet/`, never the repo root; log files stay plain text** — color and local time are view-time only (`--json` and stored logs stay raw UTC). A worker's scratch is _inside_ its run dir (`.duet/runs/<id>/scratch/`, torn down with the run, no cleanup step), and no worker deletes under `.duet/` — it holds the live run state; harness writes route through `ensureRunDir` so a stray deletion (a worker once ran `rm -rf .duet` cleaning scratch and stranded a run mid-build) self-heals on the next write instead of dying silently.
- **The health substrate stays pure** — `voices/health.ts` imports no fs/lifecycle/status, or a `status → health → lifecycle → status` value cycle closes (the fs tail-read lives in `voices/sessions.ts`, the lifecycle-needing composition in `surfaces/doctor.ts`). The whole tree carries this now: **the import direction is the trust gradient** (`registry ← run ← voices ← orchestrator ← surfaces`, `view/` a leaf) — no upward value imports. Infra classifies on every surface but auto-retries only on the headless driver (a human is present on the interactive host); that retry is **default-on for new runs** — 3, materialized at `createRun`, an old/absent budget off byte-for-byte (the `gatesAt` materialization discipline), every retry recorded in the `autoRetries` ledger.
- **AFK time caps are wall-clock, not monotonic.** A turn's cap re-checks `now()` against a fixed `Date` deadline (`runWithWallClockDeadline`; the context deadline that cuts a claude turn at 85% of its window rides the same module and abort-then-drain race), so a machine-sleep can't freeze the countdown — a monotonic timer (`AbortSignal.timeout`/execa `timeout`) stranded the audited `7447` dead-run on suspend; the build caps (`implement`, 90 min) are wall-clock too. The forced stream-watchdog env `API_FORCE_IDLE_TIMEOUT` is **Claude-only**, never set on codex, and its facts are pinned to a claude CLI version (re-verify on upgrade). Full design: `docs/automation-design.md` §"Resilience for the AFK window".
- **The interactive host's `send_prompt` is fire-and-collect,** fenced by the single-writer lease at the tool gate and the background settle; its turn lifecycle is non-throwing/total (a faulting turn flips to a collectible `failed`, never strands a role `running`); a turn orphaned by a session quit is a durable on-disk record that blocks phase-exit until `duet takeover` clears it.
- **The consultant is default-off byte-for-byte** — absent its binding, config / tool schema / snippet library / phase briefs read exactly as before. Voice asymmetries live as lane data in `src/voices/policy.ts` (never scattered per-duty checks); protocol surfaces enumerate `phaseAddressesFor`, voice surfaces `voicesFor` (and must keep the orchestrator). The checkpoint-kind split (generative frame / bet-audit `challenge` / backstop) is data too — `consultantCheckpointLive` (`src/registry/workflows.ts`) is the one gate both the briefs and `list_snippets` read, so a gateless run drops only the holding bet-audit (keeping frame + backstop) identically on both surfaces.
- **The acceptance contract is consultant-authored but never consultant-committed** — duet commits it path-scoped at the contract gate's crossing (`freezeContractAt`; full authors early at plan, blind to the technical approach; blueprint and relay author late at their Design gate, after the loop converges — the deliberate blindness trade, `docs/automation-design.md` §"Consultant checkpoints"); the author→verify chain is enforced mechanically (this-run markers + `advance_phase` rails, not prompts), and it is workflow-scoped (short authors none and stays byte-for-byte unchanged). A failed verify assertion **self-heals** — routed to the workflow's fixer duty first (`fixerDutyFor`: relay's judge, the builder everywhere else), holding only if still stuck after a bounded re-verify loop (universal). A code-changing turn at `implement` clears `verifiedAt` (`settleTurn`) — a self-heal fix, but also `reconcile-docs` and the CEO summary, which is why verify runs **last** (after docs and the packet) — so a fix structurally forces a fresh, independent re-verify before advance; whether that re-verify _passed_ is the orchestrator-recorded part (a `high` on the packet), the same trust model as triage.

## Conventions

- **Evidence-backed claims.** Workflow claims cite `examples/*.jsonl` turns or run logs; tag **(observed)** vs **(general)**.
- **Tests are behavior-through-interface.** Fake only at the seams (`docs/engineering.md` §Seams); never mock our own modules.
- **Personal tool / augmentation** — the product goals above are conventions too.
