# Test-suite consolidation — remove low-quality tests, one owner per behavior

**Status: in progress (2026-07-07, branch `testing-refactor`).** The execution plan distilled from this session's four-way audit of `tests/` (1472 tests / 56 files, all green, 5.7s). The suite's discipline is clean — zero own-module mocking, seams-only fakes, real fs/git — so this is not a rescue: it removes the two concentrated debt classes (prose-brittleness outside the parity harness, duplicated coverage without a single owner), then closes the handful of real gaps the audit exposed. Analysis details live in the session record; this file is the working checklist.

## The bar

A high-quality test measures intended behavior through a public interface and survives internal refactors. A low-quality test is trivial, restates the implementation, or breaks on internal factors (a wording improvement, a rail rename) when behavior didn't change. We remove or refactor low-quality tests rather than keep them for coverage; coverage that costs churn is debt.

Governing rules for every step:

- **Byte-level prose belongs in `tests/parity/`** (model-facing) or an explicit schema/contract pin. Elsewhere, keep the behavioral nucleus: presence/absence flips (`.not.toContain`), relational equality between two renders (`toBe` — wording-independent), recovery-token `toContain`s (a refusal must name the next move), `--json` schema key-sets, acting-command strings.
- **Wording-is-contract survives**: the health taxonomy's error-string table (matches real CLI prose), CLI refusals that name the next command, the `status --json` schema, skill↔CLI coherence scans, the snippet-library contract core.
- **One owner per behavior.** A second file may keep only its *delta* (a transport, a CLI framing, a wiring), never a re-proof.
- **No `src/**` changes in any step.** Every step is tests/ (plus docs in E1). If loosening or moving a test turns it red, that is a finding to surface, not to patch.
- **Parity pins must not move**: `git status tests/parity/pins` stays clean through the whole plan (structurally guaranteed by the no-src rule — verify anyway at E2). Wording improvements to prompts/status output themselves are explicitly deferred; this plan only removes the friction that makes them expensive later.
- One step = one commit (A2 and B1 may split into two), suite green after each.
