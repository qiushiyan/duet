# Voices and providers — binding and driving mechanics

The mechanism behind "a duty is a capability contract; a provider is an implementation": binding grammar, validation, preflight, configuration resolution, and how each provider's workers are actually driven. `docs/automation-design.md` (the spine) carries the decoupling principle, the continuity-edge concept, and the manifest freeze; `docs/interactive-transport.md` is the sibling for the opt-in interactive transport.

## The two providers

Exactly two providers exist. Their *defaults* differ — claude names a model per binding, codex inherits one from the user's config — but the binding vocabulary is symmetric: any voice may pin a model, a normalized reasoning effort, and provider-native passthrough.

- **`claude`** — Anthropic models via the Agent SDK / `claude` CLI. Configured **per-model**: each binding may name a model ID (`claude-opus-4-8`, `claude-fable-5`, …), because choosing the Anthropic model per voice is a knob the user actually turns.
- **`codex`** — the Codex CLI. The model **defaults to the user's `~/.codex/config.toml`** — the config-first philosophy, where reasoning effort, profiles, and sandbox already live and greenflag never duplicates them; absent an override greenflag passes no `-m`. A binding **may also pin a model inline** (`codex:gpt-5-codex`) when a run wants a specific one — config by default, overridable per binding.

## Binding knobs and the validation line

Beyond the model, a binding carries two more knobs, under one discipline. A normalized **effort** (`low|medium|high|xhigh`, plus claude's `max` and codex's `minimal`) maps to each provider's native reasoning-effort setting (`--effort` / `modelReasoningEffort`); and a config-only **native passthrough** hands raw provider arguments through unchanged — `claude_args` appended to the `claude` argv, `codex_config` fed to codex's `-c` overrides — the escape hatch for anything greenflag doesn't model. The discipline is the line between greenflag's *own* vocabulary and the *provider's*: the model default and the effort enum are greenflag's, so it **validates them fail-closed** at the manifest freeze — an illegal `(provider, effort)` pair (codex `max`, claude `minimal`) is rejected at `greenflag new`, because claude's CLI *silently* falls back to default on a bad effort and a silent-default overnight run is exactly the drift greenflag refuses. The native passthrough is the provider's vocabulary, so greenflag is a pure conduit — it never parses, filters, or denylists the arguments (no safety net second-guessing which flags are dangerous). What keeps that honest is a **preflight** at `greenflag new` (`src/voices/preflight.ts`), scoped to the bindings carrying an explicit model or a native override: it runs one throwaway worker turn per such binding and disposes on the provider's own verdict — a rejected argument or an unusable model **aborts run creation** with the provider's error, while anything transient or ambiguous warns and proceeds (a create-time gate must never block a healthy run on a hiccup; a case it can't positively identify degrades to fail-at-first-use, never a silent mid-build failure). So a bad binding fails *at creation, with the human present*, never hours later mid-build. Model and effort are **per-turn**, so they never enter a session's continuity compatibility — only provider (and claude transport) can degrade an edge.

## Capability contract per voice

The worker duties need session resume and streamed output; both providers satisfy these today (claude via the SDK/CLI, codex via `resume`). Workers run with **full permissions** — claude headless via `--permission-mode bypassPermissions`, codex by deferring entirely to the user's `~/.codex/config.toml` (no `--sandbox` flag) — so greenflag's coding agents are no more restricted than the user's own manual workflow (2026-06-22). This superseded a per-duty OS sandbox: codex `read-only` is a Seatbelt profile that denies *all* local writes and network, which broke even a read-only checker's own evidence tooling (a `tsx`/Node tool's `$TMPDIR` IPC socket dies with `listen EPERM`; outbound reads are blocked) *and* overrode the user's config. A checker's review-only behavior is a **prompt-level convention** (the `review-*` snippets ask for critique, not edits), not a sandbox. The **orchestrator** demands more: custom harness tools (`send_prompt`, `ask_human`, …), read-only enforcement, and pause/resume at a tool call. The claude provider satisfies this natively (Agent SDK in-process tools + `canUseTool`). A local MCP server exposing the harness tools now **exists** — the kernel is host-neutral and served over standard stdio MCP — so the harness-side half of the codex bridge is no longer hypothetical; what remains unbuilt is the codex-side wiring and its two open verification questions (pause/resume at a tool call, tool-call faithfulness) (`docs/open-questions.md` §"Codex as the orchestrator").

## Configuration and resolution

Config holds **account-level binding defaults** — the one config greenflag ships, scoped to voice→provider bindings (model, effort, native passthrough) **plus account posture** (`transport`, `budget`, and the opt-in `[corpus] dir` — a central, analysis-only archive every run's record mirrors into, fail-soft and default-absent; `docs/corpus-runbook.md`) and nothing else. The run-long voices are top-level tables (`[orchestrator]`, `[consultant]`); the duties get `[duties.<duty>]` tables. The file's full shape, with the shipped defaults, is `README.md` §"Configure" — one home, not re-listed here.

Per-run, one repeatable flag overrides any of it: **`--bind <address>=<provider[:model][@effort]>`** (e.g. `--bind builder=codex:gpt-5-codex@high --bind judge=claude:claude-fable-5`; the native passthrough is config-only, never inline). A duty alone names its stage — duty names are globally stage-unique, enforced by `validateRegistry` (an explicit `stage.duty` long form is reserved for a future collision, documented but not built) — and the run-long voices ride the same grammar: `--bind orchestrator=…` (claude-only in v1), `--bind consultant=…` (binding one implies it is on; `--no-consultant` disables a bound one for one run and wins). The shipped default when config is absent: the maker lanes and both run-long claude voices on claude/Opus 4.8 (updated 2026-06-15 from the earlier Fable-5 default), the checker lanes on codex — the cross-family review is the shipped posture. A costlier model like Fable 5 (~2× Opus) binds to any single address per run when an artifact-heavy feature warrants it.

These sources — flags, the framing's `bind.*` frontmatter keys, config, shipped defaults — resolve into the **run manifest**, once, at `createRun` (`resolveRunConfig`, `src/voices/bindings.ts`). Precedence is **per key**: each address resolves independently through flags > framing > config > defaults, so a framing that binds only the judge leaves the builder on config/defaults. The result **freezes on the run state** and `greenflag new` **echoes it** — workflow, each stage's duty bindings, consultant, degraded continuity edges, gate posture — so a run can never freeze bindings nobody saw **(observed: run `20260703-1444-717d`, created with silently-frozen defaults and abandoned)**. `voiceBindingFor` is the **one** "who runs this turn" resolver — a frozen-manifest lookup by address, no band logic, no phase parameter (a duty names its own stage) — read alike by worker construction, session identity, the context-pressure scope, stats, and takeover; a duty's session resolves its own `"stage.duty"` slot first, then walks its continuity edge, else seeds fresh (`sessionRecordFor`).

## Driving the workers

Unchanged in shape from the 2026-05-26 design: resumed CLI sessions, transcripts in the standard locations, invoked per turn by the harness on the orchestrator's instruction. Driving mechanics verified 2026-06-11 against the locally installed CLIs:

- **Codex-bound workers** (the shipped default for the checker lanes) — greenflag passes **no `--sandbox` flag**, deferring the sandbox and approval posture entirely to the user's `~/.codex/config.toml` (the `@openai/codex-sdk` adds `--sandbox` to the CLI argv only when `sandboxMode` is set, so omitting it lets the config govern). Resume is a verb (`codex exec resume <id>`) and **`--output-schema` works on resume** in codex-cli 0.133.0 (upstream issue fixed May 2026 by openai/codex#23123 — live-verified locally with a two-turn schema-enforced smoke test). Gotcha: an open stdin pipe makes `codex exec` block waiting for EOF — close stdin or pipe the prompt through it deliberately. Preferred wrapper: `@openai/codex-sdk` (thin spawn-the-CLI wrapper; rollouts still land in `~/.codex/sessions/`, so augmentation holds), pinned to the same release as the CLI, with the raw flags as known-working fallback. SDK source + docs vendored at `references/codex/`.
- **Claude-bound workers** (the shipped default for the maker lanes) — a spawned `claude -p --output-format json --resume <id>`, writing the standard `~/.claude/projects/` transcripts and drawing from the subscription credit pool (headless usage is metered separately from interactive sessions since 2026-06-15 — hence the per-invocation budget rails). An opt-in **interactive transport** (`transport = "interactive"`) drives the interactive `claude` TUI instead, so the worker's turns bill the *flat* subscription quota rather than that metered pool — built as a spike, maker-duties-only (bind it on `[duties.architect]` or `[duties.builder]`), transcript-as-truth (`docs/interactive-transport.md`). Headless permission posture: **`--permission-mode bypassPermissions`** (the user's 2026-06-11 decision) — the AFK builder edits files, commits, and runs project commands (tests, typecheck, builds) with nobody at the keyboard, and the user accepts the unprompted-execution tradeoff on their own repos. Explicit deny rules still apply, and the CLI refuses to run as root. (The interactive transport shares this bypass posture, which is why it serves the maker duties only — a read-only interactive checker would need a posture of its own.)
